# C620 / M3508 有界轮胎转动测试

本程序只测试 CAN1 的两台 C620/M3508，不发任何 DM 使能或力矩命令。启动时立即向两个 C620 槽位发送零电流。每次按键只驱动一台电机，先使用有界的 `current_raw=±550`（约 0.671 A）最多 120 ms 克服静摩擦；检测到编码器变化后降到 `current_raw=±400`（约 0.488 A），目标为按反馈编码器累计的 3 圈轮胎转数。若启动助力期间没有编码器变化，程序立即发送零电流并报告失败。速度保护需要连续 3 个新鲜反馈样本超过 550 rpm 才触发，并会打印触发时的 rpm、角度和电流，避免单个瞬态读数误停。达到目标、反馈超时、转速超限、CAN 发送失败、10 秒上限或运行中收到任意非回车键时，也都会发送两台 C620 的零电流帧。

## 上机前

- 轮子必须架空，车架和腿部可靠支撑；不要把手放在轮子、齿轮或连杆附近。
- 确认电机电源切断开关可以立即触达，并确认 DM 处于失能状态。
- 每次只测试一侧；串口用 USB_DEBUG，115200、8-N-1。命令可以按回车发送，程序会忽略终端附加的 CR/LF；等待反馈时按 `x` 或 `Esc` 取消，运行中按任意非回车键停止，`d` 发送零电流。
- 若电机转向不符合预期，立即按键停止或切断电机电源。正负号表示电机编码器方向，不等于机器人前进/后退方向。

## 按键

| 按键 | 动作 |
| --- | --- |
| `a` / `z` | C620 ID1 编码器正向 / 反向，目标 3 圈轮胎 |
| `k` / `m` | C620 ID2 编码器正向 / 反向，目标 3 圈轮胎；此前观察到变化的是 `m` 对应的负方向 |
| `s` | 显示两台最新的编码器角、rpm、电流反馈 |
| `d` / `Esc` | 向两台 C620 发送零电流 |
| 运行时任意按键 | 停止本次运动并发送零电流 |

程序根据 8192 个编码器计数/电机转、M3508 减速比 `3591/187`，按约 157313 个电机编码器计数计算一圈轮胎。每 250 ms 输出一次进度，最终显示累计电机计数和轮胎圈数估值。启动助力和正常电流均以约 7 ms 间隔重复发送；启动助力期间产生的编码器计数会计入总行程，零电流后的惯性也可能使实际圈数略超过目标。

## 构建与发送

在工程根目录执行：

```powershell
python .\softcore_apps\c620_wheel_spin\build_c620_wheel_spin.py
```

用 SecureCRT 的串口启动器发送：

```text
softcore_apps/c620_wheel_spin/build/c620_wheel_spin_frame.bin
```

这是软核 CPU 的 framed BIN，不是 FPGA `.fs` 位流。程序复用现有 `RobotApb` 地址，因此不需要重新综合位流。

## 保护边界与限制

- 单电机正常电流约 0.488 A；启动助力约 0.671 A，最多 120 ms，未检测到编码器变化就退出。单次最多 3 圈目标、10 秒正常运行上限；连续 3 个反馈样本超过 550 rpm 才触发速度保护。此前只在 ID2 负方向的 100 ms 诊断脉冲中观察到反馈变化，因此首次建议只用 `m` 验证这一方向，并仔细观察实际运动。
- 若选中电机没有新鲜反馈，程序不会开始输出电流；运行期间 50 ms 没有反馈会停机。
- 这是电流控制开环旋转测试，不是精确位置伺服；目标靠编码器计数停止，零电流后可能滑行。
- 测试只用来确认编码器方向、转速和减速比/轮速换算；承载滚动半径要在轮胎受载时另测。
