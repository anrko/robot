# 执行器与平衡数据诊断程序

这是独立的软核 C 程序，用于采集 BMI088、四个 DM4310、两个 C620/M3508 的数据，为后续平衡控制做准备。它使用当前 FPGA 位流里的 `RobotApb` 寄存器；本次只改软核程序，不需要重新综合 FPGA。

上电后程序保持安全状态：不自动使能电机，也不发送非零电流或力矩。所有电机测试都必须在车架固定、腿部有支撑、轮子架空、电机电源切断开关触手可及的条件下进行。一次只测一个电机，不要把手放在连杆、齿轮或轮子附近。

## 串口按键

串口使用 USB_DEBUG，115200、8-N-1。直接按单个字符即可，不需要输入整行。

| 按键 | 功能 |
|---|---|
| `q` | 只读查询 DM1–4 的 `Imax(0x3B)` 和 `TIMEOUT(0x09)`，不会修改参数 |
| `r` | 逐个向 DM1–4 发送失能帧 `0xFD`，请求最新的失能状态反馈；不发送使能或力矩 |
| `s` | 打印一次缓存快照：IMU、CAN 计数、DM 与 C620 最近数据 |
| `m` | 打印一条 IMU 数据：姿态角、BMI088 原始加速度/陀螺仪、采样计数和新鲜度 |
| `t` | 最多采集 10 秒只读遥测，每 200 ms 打印一次；采集中按任意键结束 |
| `d` 或 `Esc` | 向 DM1–4 发送失能帧，并向两个 C620 发送零电流帧 |
| `u` / `j` | C620 ID1 正/反向，指令 ±200，约 0.244 A，持续 100 ms 后归零 |
| `i` / `k` | C620 ID2 正/反向，指令 ±200，约 0.244 A，持续 100 ms 后归零 |
| `U` / `J` | C620 ID1 正/反向，指令 ±400，约 0.488 A，持续 100 ms 后归零 |
| `I` / `K` | C620 ID2 正/反向，指令 ±400，约 0.488 A，持续 100 ms 后归零 |
| `1`–`4` | 对对应 DM 做 +0.05 Nm、最多 150 ms 的短测试，条件满足后才开放 |

新版 `r` 会对每台 DM 显示本次 CAN0 发送 ACK/FAIL 增量和 CAN0 接收增量。必须看到 `ack` 增加、`fail=0`，并且有对应 DM 的新鲜反馈，才算失能反馈请求通过。

C620 测试会打印脉冲期间的反馈、脉冲前后快照和 CAN 发送 ACK/FAIL 增量。之前的测试显示 C620 ID2 使用 `-400` 时出现明显转速/角度变化，因此**不要重复 ID2 的 `K` 测试**。当前建议先停止进一步的有动力脉冲，确认该次测试时轮子确实架空、机构没有卡滞，并确认电机停稳。

## DM 测试：现在只做失能反馈，不做力矩测试

最近一次查询中，DM1–4 的 `Imax` 都是约 `20.522 A`，但 `TIMEOUT` 都是 `0`。达妙手册把 TIMEOUT 定义为使能状态下的 CAN 指令超时保护时间，单位每计数 50 μs；手册没有说明 0 在当前驱动固件里的特殊含义。因此 0 不是“未使能”的状态标志，电机使能状态要看反馈 `state`；也不能把 0 当作已验证的通信失联保护。按键 `1`–`4` 会被本程序的保守软件门锁住，因为它要求 `TIMEOUT>=400`（20 ms），这只是本程序门槛，不代表驱动器规定的通用最小值。不要绕过门槛或直接猜写参数。

之前版本的 `r` 有动态 CAN ID 写入漏掉 `0xC620` 写入钥匙的问题，因此会出现所有 ID 都 `NO FRESH DISABLE FEEDBACK`。新版已修正。烧录更新版后，可以用 `r` 测 DM 的**失能状态反馈和位置变化**：

1. 先支撑并固定车架，确认四个 DM 驱动器处于失能状态；不要在机械限位处用力。
2. 按 `r`。程序会对 ID1、2、3、4 各发一条失能帧，然后等待新反馈。输出应包含 `state=0x00`、正确的 `id`、`pos_raw`、速度和 `raw`。
3. 一次只缓慢移动一个关节一小段，不要强行扳闭链机构；再按 `r`。对比该 ID 的 `pos_raw`，并记下实际关节和物理运动方向。若同侧其他关节也动了，如实记录耦合关系。
4. 对四个电机重复记录。若显示 `NO FRESH DISABLE FEEDBACK`，不要按 `1`–`4`；把输出发给我检查通信/反馈触发情况。

`r` 每次都会发送失能命令，这不是纯粹的被动监听，但不会发送使能或非零力矩。它适合在支撑好的机构上触发最新失能反馈。`q` 的 `0x33` 参数回包不是电机位置反馈；程序会把它标成参数回复，避免误读。

只有在查清 `TIMEOUT=0` 的含义、通过达妙工具配置并读回合适的非零值、且实测验证停发 CAN 后驱动器会进入安全状态之后，才讨论小力矩 DM 测试。当前不需要为收集失能位置而改 TIMEOUT。

## 本次建议采集的数据

SecureCRT 开启会话日志，把完整输出保存成文本。程序不直接写 CSV 文件。

1. 上电运行后按 `q`，保存八条参数回复。当前已知 Imax 一致、TIMEOUT 为 0。
2. 按 `r` 获取四台 DM 的新鲜失能反馈。对每个 DM 记录：ID、实际关节名称、静止角度；缓慢移动单关节后再次按 `r`，记录角度变化和实际运动方向。
3. IMU 当前尚未装好时，跳过 `m` 和涉及姿态分析的 `t` 结论。等 BMI088 固定安装后，再采集正常姿态及前/后/左/右倾斜时的数据，确认安装轴向与符号。
4. C620 正负脉冲数据已有一轮。先不要重复 ID2 的 `-400`。待确认机械和供电安全后，如还需要方向验证，只在轮子架空时选一个尚未确认的方向做一次短脉冲，并记录实际轮子转向；电流符号和 RPM 符号不能代替肉眼确认的车体前进方向。
5. 手动测量轮胎接地面的外径。若要验证减速比，可在电机电源切断时标记轮子，手动转轮一整圈并记录电机反馈角度变化；不要把装配 CAD 中电机模型原点当作轮心或轴距。
6. 记录 DM ID1–4 分别对应的实际关节、可重复的站立姿态，以及安全行程范围（留出机械限位余量）。整机质量可以先称一个粗略值；精确重心和惯量可后续估算/测量。

目前已记录的 DM 最高/最低限位值只能作为当时姿态的观测值，不能直接作为几何关节角或平衡目标。当前装配体的转轴中心、连杆长度和轮心几何仍需从 CAD/实物中核实。

## 构建和烧录

在工程根目录 PowerShell 执行：

```powershell
python .\softcore_apps\actuator_diag\build_actuator_diag.py
```

通过 SecureCRT 的串口启动器发送这个带 framing 的软核镜像：

```text
softcore_apps\actuator_diag\build\actuator_diag_frame.bin
```

这是 CPU 程序镜像，不是 FPGA `.fs` 位流。验证启动器提示镜像接收成功并跳转后，使用 USB_DEBUG 串口按上述按键操作。不要把裸 `.bin`、`.fs` 或其他测试程序误发给当前启动器。
