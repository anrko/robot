# BMI088 姿态解算与电脑串口对照报告

日期：2026-10-08  
工程目录：`C:\Users\HP\Desktop\gowin\gowin\gowin`

## 目的

记录本次 BMI088 实测数据的电脑采集、FPGA 与 Python 解算对照结果，并总结陀螺仪零偏校准和磁力计的后续建议。

## 数据采集链路

- BMI088 通过 SPI 接入 FPGA，当前工程以 100 Hz 轮询读取加速度计和陀螺仪原始值。
- FPGA 使用六轴 Madgwick 解算，并通过开发板 USB_DEBUG 上的 FPGA 侧 CH340E 串口发送遥测帧。该串口应与 RK3588 的 CH9102F 控制台区分。
- 串口参数：115200 baud、8-N-1、无流控。
- 每帧包含 `A5 5A` 帧头、32 位样本序号、六轴有符号原始计数、FPGA 输出的 Roll/Pitch/Yaw（0.1°单位）及 CRC-16。
- 电脑端 `tools/imu/read_uart.py` 校验帧后，用相同的原始样本运行 Python 浮点 Madgwick 参考算法，并将原始值、FPGA 角度、Python 角度和角度误差写入 `sim/imu/live_capture.csv`。

电脑采集命令：

```powershell
python tools/imu/read_uart.py --port COM14 --output sim/imu/live_capture.csv
```

需要选择设备管理器中 FPGA 侧 CH340E 对应的 COM 口。为比较绝对角度，先运行接收脚本，再复位 FPGA，使两套解算都从初始姿态开始。

## 有效对照数据

第一次读取时日志从序号 16596 开始，电脑端 Python 解算从单位姿态开始，而 FPGA 已经运行了一段时间。这次数据存在初始状态不一致，不能用于比较绝对角度。

随后用户复位 FPGA 并重新记录。报告中的有效数据快照为：

| 项目 | 结果 |
|---|---:|
| 有效帧数 | 13,139 |
| 序号范围 | 0–13,138，连续无缺口 |
| 采样时长 | 约 131.38 秒 |
| Roll 对照 RMS / 最大绝对误差 | 0.0293° / 0.0882° |
| Pitch 对照 RMS / 最大绝对误差 | 0.0290° / 0.0586° |
| Yaw 对照 RMS / 最大绝对误差 | 0.0576° / 0.1352° |

误差定义为 FPGA 输出减 Python 输出；Yaw 差值按 ±180° 环绕处理。误差很小，表明这段采样中 RTL 与 Python 参考算法的数值结果一致。它验证的是解算实现的一致性，不是 BMI088 的绝对姿态精度。

复位后头约 5 秒，Roll 从 0° 收敛到约 37.8°，Pitch 收敛到约 1.9°。这反映传感器相对重力方向的安装姿态。后续 Roll 约在 37.6°–38.1°，Pitch 约在 1.6°–2.2°。收敛后 Yaw 在该记录中约为 0.4°–2.6°，有小幅变化，没有呈现持续单向增长。由于只有六轴数据，无法判断绝对航向；这种相对 Yaw 变化可能来自陀螺仪积分噪声/零偏，也可能包含细小实际转动。

## 陀螺仪零偏校准建议

当前 RTL 没有自动静止零偏校准。有效记录中，跳过最初 500 组姿态收敛样本后，陀螺仪原始计数均值约为：

| 轴 | 原始计数均值 | 按 ±1000°/s 量程换算的角速度均值 |
|---|---:|---:|
| X | 0.964 count | 0.0294°/s |
| Y | 0.322 count | 0.0098°/s |
| Z | 0.181 count | 0.0055°/s |

这些值来自单次记录，只能作为量级参考；真实移动、振动和温度都会影响均值。Bosch 数据手册也列出 BMI088 的零速偏置和温度变化规格。[BMI088 数据手册](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmi088-ds001.pdf)

建议在进入轮腿机器人平衡控制前增加启动校准 RTL，不需要重写姿态解算器：

1. BMI088 初始化后等待传感器静止；校准期间不要搬动机器人，也不要启动电机。
2. 以当前 100 Hz 采样率累计约 500–1000 组 `gx/gy/gz` 原始值，计算每轴均值作为偏置。
3. 校准完成后，每组原始陀螺仪数据先减去对应偏置，再进行 Q24 单位换算和姿态解算；从校准完成时重置滤波器状态。
4. 如需提高鲁棒性，可检查样本方差，检测到明显运动时继续等待或放弃本次校准。

不要在机器人运动时持续更新偏置均值，否则可能把真实的缓慢旋转当作零偏扣除。当前采集结果支持先继续推进工程；上机器人闭环控制前再完成静止校准并复测。

## 是否需要磁力计

目前不需要为了完成 Roll/Pitch 姿态估计或轮腿平衡而购买磁力计。六轴 IMU 无法单独观测绕重力方向的绝对航向；相关腿式机器人状态估计研究也明确指出，单靠 IMU 与接触信息时绝对 Yaw 不可观测。[腿式机器人状态估计研究](https://arxiv.org/abs/1805.10410)

没有磁力计时，Yaw 仍可作为从启动姿态开始的相对角度，但长期会受陀螺仪误差影响。若以后需要长期保持绝对航向，可以评估磁力计、轮编码器里程计、视觉或其他航向来源。电机和钢结构附近可能存在磁干扰，磁力计还需要合适的安装位置及校准；增加磁力计也需要把九轴数据融合接入算法。

## 结论

- USB_DEBUG FPGA 串口遥测和电脑端 CSV 对照链路已投入实测。
- 复位后从序号 0 开始的 13,139 帧对照通过，FPGA 与 Python 三轴解算差异很小。
- 当前可以接受为“传感器采集、FPGA 解算和电脑参考对照”的阶段结果；这不等于完成轮腿机器人闭环平衡验证。
- Yaw 小幅变化符合六轴航向无绝对参考的限制；短期无需为此购买磁力计。
- 进入机器人平衡控制前，建议增加上电静止陀螺仪零偏校准，并在电机运行状态下继续验证。
