# 硬件实测数据与当前结论

更新时间：2026-10-12。数据来源为本对话中的用户串口日志、既有 IMU CSV/分析报告、配套手册资料、CAD 文件检查和用户最新电机映射确认。下文将**现场观测**、**手册/铭牌参数**、**由数据计算的估计**分开。它记录了已经做过的测试，不代表整机平衡验收。

## 1. IMU 与姿态解算

BMI088 以 SPI 接 FPGA，FPGA 侧约 100 Hz 采样并运行六轴 Madgwick；遥测从 USB_DEBUG FPGA 侧串口输出。电脑脚本使用每帧相同的六轴原始值再运行 Python 参考算法。

2026-10-08 的复位后有效对照共 13,139 帧（序号 0–13,138），约 131.38 s，序号连续。FPGA 减 Python 的三轴 RMS/最大绝对误差分别为：Roll `0.0293° / 0.0882°`、Pitch `0.0290° / 0.0586°`、Yaw `0.0576° / 0.1352°`。这证明这段采样中 RTL 与 Python 算法输出相符；不是 BMI088 绝对精度认证。

静止段跳过头 500 个样本后，陀螺仪原始均值约 X/Y/Z=`0.964 / 0.322 / 0.181 count`，按 ±1000°/s 档估算为 `0.0294 / 0.0098 / 0.0055°/s`。属于一次记录的估值，不是生产标定值。启动时静止校准仍有价值。六轴没有绝对航向观测，Yaw 的长期漂移预期存在；短期俯仰平衡不要求磁力计。

安装姿态收敛时曾观察到 Roll 约 `37.6–38.1°`、Pitch 约 `1.6–2.2°`。这是传感器相对机体的安装角表现，后续装机/重装时应重新核对轴向与直立零点。

细节、采集口径、复位前无效记录说明及 CSV 路径见 [`docs/imu/本次对话总结与实测分析.md`](imu/本次对话总结与实测分析.md)；原始采样在 `sim/imu/live_capture.csv`。

## 2. CAN 与 DM4310

### 通信和 ID

- CAN0 连接 DM4310；CAN1 连接 DJI C620/M3508。FPGA 双 CAN 之前已经用 USB-CAN/串口测试分别验证过收发。
- CAN0 的 `ESC_ID` 参数读测试中，DM ID 1、2、3、4 都逐一回应了对应 ID；后续软核运行反馈按数据字节 D0 低 4 位分出四台电机。
- DM 参数查询日志连续出现 `ACK+1 / FAIL+0`；短暂逐个使能再失能探测曾收到 state `0x01` 后 `0x00` 的新鲜反馈。它只验证控制报文和状态反馈链路，不代表关节闭环或失联保护通过。
- 2026-10-12 用户确认当前实体映射：`SOLID`、`SOLID001`、`SOLID002`、`SOLID003` 分别为 DM4310 ID1、ID2、ID3、ID4。该映射覆盖此前“只知道 ID、未知道实体位置”的临时记录；后续控制按此映射使用，但电机正方向仍需小幅动作实测。

### 读出的参数

四台读取的 `Imax (0x3B)` 原始值均为 `0xDA2DA441`，程序按 IEEE-754 解为约 `20.522 A`。四台 `TIMEOUT (0x09)` 均读回 `0` ticks，手册计数单位为 `50 μs/tick`。含义：现场读值是 0；**0 的该固件语义及使能时实际失联动作没有被验证**。不能据此声称有通信保护，也不能仅因为值为 0 就判断电机坏或不能动。诊断应用设置的 `TIMEOUT>=400`（20 ms）只是软件运动门槛，不会写电机参数。

另一次旧诊断输出把读取 0x09 的回包错按成位置/速度字段（出现 `0x33` 和 `-27.891 rad/s`）；该解析输出无效，不能当成 DM 的真实速度或位置。应以参数原始回包/后续正确解析为准。

### 失能状态机械行程采样

用户按 ID1→ID4 记录了上限位到下限位/站立端的反馈。旧诊断程序把位置字段按 `PMAX=12.5 rad` 映射后得到：

|---:|---:|---:|---:|
| 1 | -0.883 | +0.872 | +1.755 |
| 2 | -2.743 | -4.461 | -1.718 |
| 3 | +2.206 | +3.943 | +1.737 |
| 4 | +0.786 | -0.917 | -1.703 |

原始计数变化同一轮记录约 ID1 `+4622`、ID2 `-4502`、ID3 `+4579`、ID4 `-4499`。趋势显示 1/3 和 2/4 的计数方向成对相反，行程幅度相近。

**重要限制：**解析出来的角包含超出 ±π 的数值，与 DM 手册关于上电位置范围及该接收解析路径存在待核对点。因此上表是历史程序的解析输出和手动行程趋势记录，不是已标定的关节几何角、软件零位或闭环目标角。控制前要核查原始帧、协议字段（包括 `p_m`/`xout` 等寄存器）和回绕规则，并实测实体关节映射及符号。更多注释见 [`docs/balance/fpga_balance_bringup.md`](balance/fpga_balance_bringup.md)。

## 3. C620 / M3508

### 连接和通信

- 两台 C620 在 CAN1 同一总线上；2026-10-12 用户确认 `R_M3508` 为 CAN1/C620 ID1，`L_M3508` 为 CAN1/C620 ID2。按当前 CAD 坐标，ID1 是右轮，ID2 是左轮。该记录覆盖此前只按侧面 A/B 命名的临时说法。
- DJI 组电流命令使用标准 CAN ID `0x200`、DLC 8；ID1 命令放 D0/D1、ID2 放 D2/D3。反馈帧分别为 `0x201`、`0x202`。
- 早期接线调整后，ID1/ID2 的反馈计数均递增，CAN1 发送零电流帧时 ACK 成功；电机架空时反馈 rpm 多为 0，电流 raw 在零附近小幅噪动。

### 有界转动实测

用户最新的软核测试使用 `current_raw=400`（日志标注约 `0.488 A`），只驱动单侧并持续发送，随后发两侧零电流。日志显示 CAN1 ACK 增长且 fail delta 为 0。

| 电机 | 按键/命令方向 | RUN 中反馈 rpm 观察范围 | 结束结果 | 备注 |
|---|---|---:|---|---|
| C620 ID2（左轮） | `k`；程序方向 `+1`，RUN `current_raw=+400` | 约 `+234–+372 rpm` | `motor_ticks=416629`，估算 `2.648` 圈轮胎；结束时 rpm=0 | 用户提供的 `k` 测试日志。STOP 行写“30 s time limit”；与 RUN 行宣称的 10 s 上限不一致，不能据此确认实际运行时长。 |
| C620 ID1（右轮） | `a`；程序方向 `+1`，RUN `current_raw=+400` | 约 `+343–+498 rpm` | `motor_ticks=476306`，估算 `3.027` 圈；达到目标后零电流，rpm=0 | 用户提供的 `a` 测试日志。RUN 行写 3 圈目标、10 s 上限，记录显示到达编码器圈数目标。 |

当前 `c620_wheel_spin` 程序按键映射为：`a`→ID1 正命令（`+current_raw`，预期编码器计数正向），`z`→ID1 负命令，`k`→ID2 正命令，`m`→ID2 负命令。正负号是**软件命令约定**；`a/k` 两段历史日志证明对应电机在正电流命令下转动、遥测 rpm 为正。日志没有记录观察者相对机器人/电机轴的视角和轮子实体转向，因此不能据此写成“车体前进”或“车体后退”。ID1、ID2 的轮子实际前进方向及左右镜像后的符号仍要架空观察后确认。代码键位定义见 [`softcore_apps/c620_wheel_spin/main.c`](../softcore_apps/c620_wheel_spin/main.c)。

计数估算使用 8192 counts/转和 M3508 减速比 `3591/187 ≈19.2032`，约 157,313 电机计数/轮胎转。这个测试证明当前开环电流命令能让两侧轮子转动、C620 编码器计数在变化；不能证明承载机器人时的轮端力矩足够、左右前进方向一致或平衡可用。测试时轮子架空，停止后有惯性。

此前更短的 raw `±200`（约 0.244 A）、100 ms 脉冲曾只看到很小的角度变化；后续 raw `400` 的持续测试有清楚的 rpm 和计数变化。因此“脉冲看起来不动”不等价于 CAN/电机故障。

### 启动助力与速度保护复测（2026-10-11）

为处理 `raw=400` 偶尔不能克服静摩擦的问题，软核测试程序增加了限时启动助力：先发方向对应的较大电流，检测到编码器开始变化后切回 `raw=400`。第一版使用 `raw=700`、150 ms；用户实测中 CAN 发送无失败（`ack/fail=1570/0`），但多次触发 550 rpm 速度保护，其中一次在进入正常电流阶段后停止，后续尝试则在启动助力阶段停止。不能仅凭这些日志确定是电机真实超速还是单个速度反馈瞬态，但旧程序对单次越限立即停车过于敏感，且启动助力偏强。

随后测试镜像调整为启动助力 `raw=550`（按 C620 标称映射约 `0.671 A`）、最长 120 ms，编码器有变化后回落到 `raw=400`（约 `0.488 A`）；速度保护改为连续 3 个新鲜反馈样本超过 550 rpm 才停车，并打印触发时的 rpm、角度和电流。用户确认烧录该版本后相关方向测试均正常。此次没有附上新版逐次运行日志和峰值 rpm，因此记录为**用户确认测试通过**，不补写未提供的精确转速或转数。

该启动助力是架空轮/执行器验证用的短时补偿，不等于已经确定平衡控制的启动参数。进入整机控制后仍需根据负载、左右方向和车体状态重新做斜坡限幅与静摩擦补偿；过速、反馈超时、CAN 失败和急停仍必须能立即归零。

### 手册/轮胎信息（不是本轮台架实测）

配套 M3508/C620 资料给出减速比 `3591/187≈19.2032:1`，额定转速约 469 rpm，M3508 额定电流 10 A、额定转矩约 3 N·m、转矩常数约 0.3 N·m/A；C620 电流命令约 `raw ±16384 ↔ ±20 A`。这些是手册条件下的规格/近似换算，不应把电调输入电流、相电流命令和轮端扭矩混为同一实测量。

用户轮胎标签：RISING SUN 5x2A，标称外径 125 mm、宽 40 mm、内径 92 mm、单胎 0.17 kg；标称未承载半径为 62.5 mm。车上承载有效半径尚未测量。

## 5. 当前仍需补齐的实测项目

1. **IMU**：当前安装轴向、机身直立时 pitch 零点、启动静止陀螺仪偏置；静置采样并手动小角度前后倾斜验证符号。
2. **DM**：已记录 ID1..4 到 `SOLID`..`SOLID003` 的实体映射；仍需纠正/校验角度字段与回绕、确认各关节正方向，读取并设定非零通信超时，再验证停发帧后的实际失能动作。未验证前不做有力矩平衡测试。
3. **轮子**：用承载滚动距离校准有效半径；分别架空小电流确认 ID1/ID2 的车体前进方向、rpm 符号及减速比换算。
4. **机构**：由当前装配体或实体测四个转轴中心、连杆长度、轮心到机身参考点的位置和合法腿长；限位之外留出软件裕量。
5. **整机**：称量成机质量，按 CAD/BOM 估算重心与惯量并留误差范围；确认急停/电机电源切断能够快速操作。
6. **闭环**：先使用防倒支架，小增益确认姿态符号、轮向、关节力矩方向；当前只能说控制框架和执行器接口已具备继续开发条件，不能说机器人已可稳定平衡。
