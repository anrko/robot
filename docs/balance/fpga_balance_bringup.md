# FPGA 轮腿平衡控制准备

## 当前机械与总线映射

根据 `R6R4_D03_assembly.FCStd`、当前接线和用户在 2026-10-12 的确认，控制侧使用以下逻辑编号：

| 设备 | 总线 | ID | 用途 |
| --- | --- | ---: | --- |
| DM4310 | CAN0 | 1 | CAD `SOLID`，右侧 `+X,+Z` |
| DM4310 | CAN0 | 2 | CAD `SOLID001`，右侧 `+X,-Z` |
| DM4310 | CAN0 | 3 | CAD `SOLID002`，左侧 `-X,-Z` |
| DM4310 | CAN0 | 4 | CAD `SOLID003`，左侧 `-X,+Z` |
| C620/M3508 | CAN1 | 1 | `R_M3508`，右轮 |
| C620/M3508 | CAN1 | 2 | `L_M3508`，左轮 |

CAD 坐标约定为 `X=左右、Y=上下、Z=前后`，其中 `+X` 为右侧、`-X` 为左侧；`+Z` 对应截图上方还是下方，需要在机器人上指定前方后再固定“前/后”名称。用户已经确认 DM ID 与四个 `SOLID` 实体的对应关系，以及右/左 M3508 的 CAN ID。CAD 和编号仍不能推断电机旋转正方向、机械零位或关节角符号。

CAN1 的 C620 组命令使用标准 ID `0x200`：C620 ID1 使用数据字节 D0/D1，C620 ID2 使用 D2/D3；D4～D7 在当前只有两台 C620 时保持为零。两台 C620 是同一条 CAN 总线上的节点，不是分别占用不同的 CAN 控制器。

DM4310 的 MIT 控制帧使用标准 ID `1..4`，每帧 8 字节；四台电机的反馈帧 CAN ID 都是配置的 Master ID（当前为 `0`），电机 ID 在反馈数据 D0 的低 4 位，错误状态在高 4 位。不能通过反馈帧 CAN ID 区分四台电机。C620 的两台电调共用 `0x200` 组命令，反馈为 `0x201` 和 `0x202`。C620 组帧的四个有符号电流槽位分别对应电机 1、2、3、4；当前只使用槽位 1 和 2，另外两个槽位必须保持为零，直到确认总线上还有其它电机。

PMAX/VMAX/TMAX 与 `dm_runtime_probe` 当前换算一致，无需为这四台修改比例。减速比 10 是电机配置，不能再对已按协议解释的输出轴位置盲目除以 10。

资料包 V1.4 手册说明 KT_OUT 在电机参数辨识准确时设为 0；因此不能把截图中的 0 直接理解为电机不能输出力矩。截图中的 KP_MAX/KD_MAX 为 0 的含义尚未确认，不把它们当作后续 MIT 报文中实际发送的 Kp/Kd。不要据此修改辨识、校准或驱动参数。

手册说明 CAN Timeout 以 50 us 为计数周期、在使能时生效，但当前资料没有明确解释数值 0 对此固件的特殊含义。实际有力矩运行前必须配置并验证通信丢失保护，不能把“CPU 停止发帧”当作已经验证的失能。超时时间需按后续控制频率和调度延迟确定。

用户运行探测应用后，四台反馈均由状态 1（使能）转为 0（失能），ID 分类正确、计数递增。日志中静止位置约为 ID1=0.265 rad、ID2=-2.644 rad、ID3=2.779 rad、ID4=-0.846 rad；这些只是当时的位置，尚无参考姿态照片，不作为机械零点。

| 1 | -0.883 | 0.872 | +1.755 | `0x00`, id=1 | `0x00`, id=1 |
| 2 | -2.743 | -4.461 | -1.718 | `0x00`, id=2 | `0x00`, id=2 |

两端行程约为 1.70～1.76 rad（约 97～101°）。ID1/ID3 与 ID2/ID4 的行程符号相反，符合左右或镜像机构的常见情况，但仍需用“单关节小幅移动”实测确认软件正方向。站立参考角可先取上表的第二列（最低限位附近）作为记录值，但控制目标应留出机械限位裕量，不能把限位角直接作为长期闭环目标。

两组记录中的速度约为 `-0.008 rad/s`、力矩在约 `±0.04 Nm` 内、温度约 28～31 °C，且状态均为 `0x00`（失能），说明采样时电机基本静止、温度正常。后续校准建议在机械限位前留出安全余量，例如先把目标放在每个行程端点内侧 0.1～0.2 rad，再通过腿长/机身水平实测调整。

新版应用 `r` 命令只发送失能帧并读取新反馈，适合记录参考姿态与小幅手动移动前后的角度；`s` 仅打印缓存。关节方向、参考姿态、IMU 轴向、轮子反馈/命令方向仍需确认。

`wheel-legged-master/硬件/打印件版/代码/DM-balance打印件版本/DM-balanceV1` 给出了完整的控制分层：

1. BMI088 姿态解算，输出俯仰角和俯仰角速度。
2. 读取四个关节的角度和角速度。
3. 四连杆正/逆运动学，将关节角转换为腿长、腿杆角和导数。
4. LQR 计算轮力矩、机身俯仰补偿和腿部支撑力。
5. VMC 雅可比矩阵将腿空间力/力矩变成两个关节力矩。
6. MIT 帧发送到 DM4310，C620 组帧发送轮电流。

其中的连杆长度、零点、LQR 多项式和电机正负号只适用于它的 3D 打印版本。必须用当前 CAD 和实物重新确认，不能直接复制参数。

## FPGA 侧必须补齐的接口

原 `dm_can0_test` 只发送 `0x7FF` 的 `ESC_ID` 参数查询，其返回的 `01/02/03/04` 只证明相应电机能响应参数读取。后续 `dm_runtime_probe` 已在板上确认四台运行反馈和使能/失能状态；状态反馈也可由失能帧触发，无需为测角反复使能。

当前 RTL 已增加 CAN0 动态 TX ID 和按反馈数据 D0[3:0] 分类保存 ID1..4 的 MMIO；发布位流 `camera720_imu_softcore_can2_dm_feedback.fs` 已生成，用户运行探测应用确认四台数据分别进入对应寄存器。闭环前仍需完善控制数据发送、超时保护和现场参数确认：

- 让 CAN0 的发送 ID 由 MMIO 动态选择，依次发送 DM4310-ID1、2、3、4 的 MIT 帧；
- 用新位流验证 CAN0 对 Master ID `0` 的接收及 D0[3:0] 对 ID1..4 的分类；
- 增加 DM 反馈解析（位置、速度、力矩、温度和状态）；
- 保持 CAN1 的 `0x200` 组帧，编码两侧 M3508 的电流命令；
- 在软核中加入 1 kHz 采样、超时失能、姿态/关节角/电流限幅和显式使能键；
- 上电、超时或姿态超过阈值时，所有 DM 和 C620 命令进入经手册确认的安全状态；仅停止发帧不一定等同于 DM 失能。

## 建议的上机顺序

1. 机械卸载或加防倒支架，保持电机失能；先验证 BMI088 数据和 M3508 的 `0x201/0x202` 反馈，再重新综合并验证新的 DM MMIO 分类逻辑。
2. 查清 DM4310 的运行模式反馈条件，在机械固定、急停可用的条件下逐个验证运行反馈；不要用 `ESC_ID` 参数回包代替关节状态。
3. 单独验证 DM4310 使能/失能报文与状态反馈，确认实际安全状态；暂不发送非零力矩。
4. 对每个关节施加很小的限幅力矩，确认角度变化方向与软件约定一致，立即失能。
5. 轮子架空，验证 M3508 的正负电流方向和反馈转速方向；CAN1/C620 ID1 是右轮，ID2 是左轮。
6. 实现“腿长保持”而不是完整平衡，记录姿态、关节角、轮速和命令，确认闭环符号正确。
7. 最后才在防倒支架上开启小增益俯仰平衡，并逐步增加力矩限幅。

## 软核平衡框架（2026-10-10）

已新增 `softcore_apps/balance_control`，它是正式控制程序的独立目录，沿用当前 `RobotApb` 寄存器，不改变 FPGA 位流。程序包含 1 kHz 定时器入口、DM/C620 反馈采样、DM MIT/C620 组帧、CAN 新鲜度检查、SAFE/ARMING/ACTIVE/DISARMING 状态机，以及 `balance_compute()` 的 LQR/VMC 预留接口。

当前编译配置为 `BALANCE_IMU_STUB=1` 和 `BALANCE_OUTPUT_ENABLE=0`：上电只发送 DM 失能和 C620 零电流安全帧，姿态无效时拒绝 `a` 命令，不会驱动机器人。生成镜像的脚本是 `softcore_apps/balance_control/build_balance_control.py`；当前检查结果为裸镜像 11476 bytes、framed 镜像 11486 bytes，SHA-256 为 `37cc650be3bf3436bb986bc96d5b24dab97fdfbd08a10d85eb25ec94b0201ab7`。这只是软件镜像，不需要重新综合 FPGA。

框架还不能直接完成平衡。必须先补齐 BMI088 轴向/零偏/量程、ID 到物理关节的映射与正方向、轮半径和轮速/电流方向、连杆几何、质量和重心、站立参考姿态，以及 DM/C620 的通信失联保护验证。只有这些数据经过架空测试和防倒支架测试后，才允许把 IMU 占位关闭、实现 `balance_compute()`，最后再打开 `BALANCE_OUTPUT_ENABLE`。

## 仍需现场确认的数据

- CAD 坐标中 `+Z` 哪一侧定义为机器人前方，以及各关节的机械正方向；DM ID 1..4 的实体位置映射已经确认；
- 四个关节的机械零点、减速比、正方向和角度范围；
- 两个 M3508 的轮半径、减速比和正方向；
- BMI088 安装方向与软件 `pitch/gyro` 轴的对应关系；
- 机身质量、腿部质量和支撑几何，用于初始 LQR/VMC 参数；
- 可立即切断电机动力的急停方式。

在这些数据确认前，现有“CAN 查询通过”只能证明通信链路正常，不能证明机器人已经具备安全的自平衡控制条件。

| C620 命令范围 | `-16384 … +16384` | 对应转矩电流约 `-20 … +20 A`；单个槽位为有符号 16 位高低字节 |
| C620 连续最大允许电流 | `20 A` | 这是 C620 在资料条件下的持续允许值，不等于 M3508 的额定电流；平衡控制应优先遵守 M3508 额定 10 A |

若 `n_rpm` 是 C620 反馈的转子 rpm，轮速的参考换算为：

```text
n_wheel_rpm = n_rpm / 19.2032
v_m_s       = 2π * R_wheel * n_rpm / (60 * 19.2032)
```

把轮胎未承载标称半径 `R_wheel = 0.0625 m` 代入时，`1 rpm` 转子转速约等于
`0.0003408 m/s` 轮缘线速度；实际应以承载有效半径替换。若采用反馈电流原始值 `current_raw`，可先用：

```text
I_A       ≈ current_raw * 20 / 16384
T_wheel   ≈ 0.3 * I_A    (仅为近似，需实测校正)
```

C620 手册规定“面向 M3508 电机轴时，轴逆时针为正转”。这只是电机轴的定义；
装到机器人后，左右镜像、轮胎安装方向和 CAN ID 映射可能使车体前进方向出现正负号，
因此必须把机器人架空，分别给 ID1 和 ID2 一个很小的正电流，记录 rpm 和实际前进方向，
再写入 `wheel_sign[2]`。在这个实测完成前，不能在平衡控制中假定两个轮子的符号相同。

本项目当前记录为：C620 ID1 接右侧 `R_M3508`，C620 ID2 接左侧 `L_M3508`；控制帧为 `0x200`，
槽位 1/2 分别使用 D0/D1、D2/D3，未使用的 D4～D7 保持零。

### DM 位置映射的一个待核对点

当前 `dm_runtime_probe` 按四台驱动器的 `PMAX=12.5` 将 16 位位置字段映射到
`[-12.5,+12.5] rad`。手册同时写明“上电后电机位置输出限定在 `[-π,+π] rad`”。
本次实测记录中的 ID2=`-4.461 rad`、ID3=`3.943 rad` 已超出 `±π`，因此这些值在闭环前
只能作为当前解析器的相对位置记录，不能直接当作几何关节角。下一次上电后在同一机械位置
读取原始 16 位字段，并分别读取参数 `0x50 (p_m)`、`0x51 (xout)`，确认固件实际输出的
变量和映射范围；在确认前不要把 `-4.461/3.943` 写成平衡目标或限位阈值。

## DM4310-2EC 安全限值与通信失联保护

资料包中的 `DM-J4310-2EC V1.2 使用说明书 V1.4` 给出的 24 V 版本参数为：

| 项目 | 手册值 | 解释 |
| --- | ---: | --- |
| 额定相电流 / 电源电流 | `4.9 A / 3.1 A` | 额定工作点参考，适合连续运行限值的上限依据 |
| 峰值相电流 / 电源电流 | `20 A / 16.5 A` | 只能作短时峰值参考，不能作为持续平衡电流 |
| 额定 / 峰值输出力矩 | `3.5 N·m / 12.5 N·m` | `TMAX=10` 是 MIT 浮点映射范围，不表示可以持续输出 10 N·m |
| 额定 / 空载最大转速 | `120 / 200 rpm` | 输出轴参数；另有电源、电机磁链等限制 |
| 减速比 | `10:1` | 已配置在四个驱动器中，不要再对已经解码的输出轴位置重复除以 10 |
| 过温保护 | 驱动 MOS 约 `120 ℃`；线圈保护值可设，手册建议不超过 `100 ℃` | 进入保护后退出使能 |
| 过流保护 | `OC_Value` 范围 `(0,1)`，默认约 `0.8`，建议不超过 `0.98` | 相对于驱动器最大相电流的百分比；实际最大值应先读取只读寄存器 `Imax(0x3B)` |

MIT 的 `PMAX/VMAX/TMAX` 是接收命令的等比例映射范围。当前四台的配置为
`PMAX=12.5 rad`、`VMAX=30 rad/s`、`TMAX=10 N·m`，所以软件打包必须继续使用这组范围；
真正的安全限制应在 FPGA/软核另外做一层。建议调试阶段依次使用“失能反馈 → 小幅位置保持 →
很小的力矩限幅”，连续控制不要超过额定 `3.5 N·m`，峰值 `12.5 N·m` 仅作为驱动器的短时
边界参考。第一次架空测试应从远低于额定值的力矩开始，并保留硬件急停。

通信失联参数 `TIMEOUT(0x09)` 的单位已经明确：驱动器在使能状态下，连续经过设定的计数周期
仍未收到 CAN 指令就保护退出，每个计数周期为 `50 μs`。因此：

```text
timeout_us = TIMEOUT * 50
```

四台当前读到的 `TIMEOUT=0`，手册没有说明该固件中 0 是“关闭保护”还是特殊的立即超时值，
所以不能把它当成已经验证的失联保护。当前软核每 1 ms 只提交一个 CAN 帧、DM 帧按轮换槽位发送，
单个 DM 的发送间隔还会受槽位和 CAN 仲裁影响。正式使能前应先在失能状态配置一个非零值，
例如先按实测发送间隔选择 `400`（约 20 ms）量级，再单独停止发送，确认反馈状态进入失能/错误状态，
随后才决定最终值。这个建议值不是手册默认值，必须用实际调度周期和急停测试验证后才能写入并保存。

DM 反馈帧的 CAN ID 是 `Master ID`（当前为 0），电机 ID 在 D0 低四位，状态在 D0 高四位；
状态 `0` 为失能、`1` 为使能、`D` 为通信丢失。因而不能只看 CAN 接收计数，必须同时检查状态位和
新鲜度，并在超时、姿态超限、温度超限或软件故障时发送明确的失能帧、C620 零电流帧并切断电机动力。
